# 第四阶段：工程验证与交付

> 本阶段只验证项目实际启用的**工程约束**，不再运行第二轮文学评分。七维评分、37项 AI 味裁决、自动改稿上限按 [review-core.md](../guides/review-core.md)。

## 1. 读取交付配置

读取 `novel.project.json`、`AGENTS.md`、正文源、状态文件与输出目录；确认本项目是否维护 TXT/合订本和可用的脚本。没有的目录、状态字段或输出格式不强制创建。仅项目已有写作计划状态文件时才更新其 status。

## 2. 工程核验

- 检查正式正文文件存在、章节编号/顺序和作者审批记录，区分实际已读与未读取内容。
- 对需要的项目调用真实可用的脚本。例如：`python {skillBaseDir}/scripts/check_chapter_wordcount.py --all <项目目录> --json`；其他脚本先查看参数与配置再调用。篇幅只影响工程门禁，不记文学 P 级或七维扣分。
- `scan_ai_tone.py` 是可选机械候选定位，优先用于新改或缺可靠记录的正文；命中先人工核实，脚本 PASS 不代表37项语义审查完成。
- 工程异常记录路径、检查命令、退出码、原因、修复与复验；仅复验受影响范围。

## 3. 安全修复与轮次

若项目允许自动工程修复，可对有明确可执行修法的工程问题尝试最多3轮，**不因工程检查不通过而自动从头重写正文**。工程3轮与质量审稿最多5轮互不混用，也不能成为额外的文学润色授权；需要作者裁决、缺证据、权限不足或耗尽轮次时停止。未确实通过的项目不得标为 completed。

## 4. 项目启用 MD→TXT/合订本时才导出

适用且脚本参数已核对时：

```bash
python {skillBaseDir}/scripts/export_reading_txt.py --project-dir <项目目录> --all
python {skillBaseDir}/scripts/export_reading_txt.py --project-dir <项目目录> --all --check
```

只改唯一权威源，再导出副本并核对章节顺序、标题、段落与内容。未执行检查不得写同步 PASS；项目没有此类副本要求时标不适用。

## 5. 交付结论

分别报告文学质量、AI味专项、工程交付、导出副本同步的真实状态与阻塞；不以字数、脚本状态或机器命中推断作者身份或文学总分。
