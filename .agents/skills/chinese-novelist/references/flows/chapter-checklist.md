# 逐章创作流程（统一轻量版）

> **执行优先级**：[Skill 主入口](../../SKILL.md) → [审稿核心协议](../guides/review-core.md) → [正文默认模板](../guides/chapter-review-default.md)。本文件只编排创作阶段；历史 G1—G4、八维审读和专题手册不能叠加为第二套评分或门禁。目录、文风、字数、审批、导出格式均读取当前小说项目配置及确认资料。

## 1. 规划与写前核对

1. **卷纲 → 章纲 → 章节简写 → 正式正文**。按当前作品确定的审批制度逐章推进；未获准的未来内容不得当作已发生事实回写。
2. 依当章任务加载相关卷章纲、邻近正文、人物小传、关系、地点、组织、时间、伏笔及视角知情边界。先确定各角色的目标、利益、能力限制和当场处境；反复出场或推动关键情节的角色需要可核对的人物小传，纯一次性背景角色不强制建复杂档案。
3. **专业知识按题材触发**：战斗、医疗、法律、交通、历史、超自然等只有实际涉及才读取对应规则，检查行动条件、资源、身份、支援、代价与后果。
4. 需要第三视角/跨阵营插章时，确认其自身有新的判断、行动及后果，而非重复场景或提前泄露秘密；插章编号、篇幅及审批遵从项目配置。

## 2. 备料、起草与初稿自检

- 可以参考 [v8 十段资料包](webnovel-writer-v8-adapter.md) 备料；只有真实具备相应运行环境才能使用原生上游工具或独立子Agent。
- 正文以人物的目标、行动、对方反应和真实后果推进；逐个说话人核对声口、现场沟通目的、关系与信息边界。避免公文式绕弯、多人统一口吻、无作用的微动作、责任宣言和过密修辞。
- 每个自然段检查其事件、情绪、关系或伏笔增量，同时保护有功能的慢场景、专业手续、反复、留白和自然口语。**不设通用固定对白百分比、高潮次数、首段套路、强制反转或钩子配额**。
- 格式、目录、长度按项目配置。参考 [章节结构模板](../guides/chapter-template.md) 时不可把备料备注混入正文。

## 3. 综合语义审查、反证与正收益改稿

1. 正式正文按 [review-core.md](../guides/review-core.md) 同轮审查五类问题，并按 [37项原表](../guides/ai-style-37-checks.md) 逐项裁决；章纲和简写只走 [剧情模式](../guides/outline-review.md)。
2. 可选脚本只负责机械候选定位。旧四关、S/F/TR/TX、PAM、朱雀等**按疑点取证，不另设一整轮审稿**；同一根因只列一个主问题并扣一次分。
3. 主审逐项核查原文、阅读损害、反证和改稿净收益。独立反方真实可用才派生，否则明确单模型反证；主动质量审查按核心协议的授权、评分阈值和轮次自动修订及复验，不能因机器候选强改。
4. 分开记录七维质量、37项专项、实质P0/P1和工程交付；未实际执行的步骤不得声称已完成。

## 4. 事实回写与交付

- 仅确认并写入正式正文的事实可以回写人物、时空、关系、资源及伏笔账本；未批准简写、传闻、猜测和未来计划不当作已发生。
- 按 [phase4 工程验收](phase4-validation.md) 检查当前项目启用的编号、篇幅、审批、导出格式和同步。只有维护 MD/TXT/合订本的项目才做对应导出，唯一正文源不得被派生副本反写。
- 留存真实读取范围、审查结果、净收益修订与回滚、命令运行结果和阻塞。旧[四关案例库](../ai-tone/README.md)和[扩展审查清单](../guides/novel-review-checklist.md)作为经验资料随需查阅。
