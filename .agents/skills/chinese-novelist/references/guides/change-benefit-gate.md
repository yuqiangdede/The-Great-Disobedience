# 改稿净收益评估门禁（Change Benefit Gate，所有修改必经）

> 适用：已批准简写、候选稿、已定稿正文、第三方视角插章、章节/分卷规划、人物小传、权威设定、事实账本及对外发布的审稿修订建议。由 chinese-novelist 统一总控，内置 v8 改稿工作流、G1—G4 去 AI 味、独立反方审稿及批量自动修复共同执行。**发现问题 ≠ 必须采用该修改方案；“修改后确实更好”才是放行条件。**

## 1. 不可跳过的原则

1. **每个实质修改先比较好处与坏处，预计净收益明确为正，才允许实施。** 不以“审稿人提出了建议”“修改更漂亮”“扫描器出现 WARN”“版本越新越好”代替收益证明。
2. **保留原文是有效且默认的决策。** 收益小于或等于代价、证据不足、结果难以判断时，判「不改/待核」，保留原文并说明理由；不得为了体现工作量而强行润色。
3. **先诊断问题，再挑选代价最小的可行解。** 若某方案弊大于利，必须尝试更小范围、保留关键信息的替代方案，或拒绝这次修改；禁止全局换词、批量抹平语言、无授权重写。
4. **硬性错误不能被“暂时不改”洗成 PASS。** 时间轴、生死、伤病、装备、权威设定、人设、关键因果等确证的 P0/P1 或现行硬门禁问题，若候选改法负收益，寻找净收益为正的其他修复方案；找不到就维持 BLOCKED，记录冲突并交作者裁决，不得交付为通过。
5. 作者明确要求的修改也应评价利弊。能用更小代价达到目标时先采用低损方案；若需求与既定硬约束或重要叙事目的冲突，说明代价与可选路径，不假装没有副作用。**不得据此越过既有用户审核或正文改动授权。**

## 2. 修改前逐项判断（每个候选改动必填）

以**单个可独立回滚的改动点**为评估单位；删改句段、调整场景顺序、增删插章、改人物关系、补逻辑、改设定、事实账本更正等均须逐项判断。多处同类批改可汇总共性风险，但每个落点都要核对，不能用一个结论放行整批。

| 字段 | 必须回答 |
|---|---|
| 修改 ID / 定位 | 对应问题编号、版本、章节/文件与原文位置；证据是否成立 |
| 原文功能 | 原文目前在传递什么信息、角色特征、节奏、情绪、伏笔或连续性锚点 |
| 候选动作 | 具体增删改位置、最小可执行方案；必要时附不修改/其他改法 |
| **预期收益** | 可读性/吸引力、人物可信度、因果与连续性、信息释放、节奏、语言自然度等，**具体改善什么** |
| **潜在损害** | 是否削弱人物差异、戏剧张力、情绪积累、伏笔、群像/第三视角、生活质感、信息边界、世界观与伤病装备连续性；是否牵连邻章/账本 |
| 证据与比较 | 用原文与拟改片段或改前/后版本比较；标注受益/受损的程度（高/中/低）及不确定性，**不伪造精确分数** |
| 决策 | `执行（收益明确 > 损害）` / `改用替代方案` / `保留原文` / `待作者裁决`；必须写理由 |

**特别防误伤**：
- 去 AI 味：删掉套话可能改善语言，但若伤及角色声口、自然口语、节奏或有意复沓，净收益不一定为正；词频及自动扫描结果只是候选证据。
- 去冗余：压缩逐一救人/战斗流程可能提速，但不能抹掉有独特选择、代价、关系变化的慢戏；重复首次/再次可能承担不同功能。
- 补解释：补齐战术、阵营动机或科技设定可能增强可信度，也可能让读者被灌输说明、提前剧透；优先通过情节中的可见后果解决。
- 插章/结构调整：增加外部视角可能建立复杂性，也可能打断连续悬念、稀释主线；以独立事件价值与信息增量判断是否值得。
- 状态/设定同步：以已确认正文与唯一权威源为准，修正衍生摘要需降低未来误写风险，不能倒过来为了满足旧摘要改动已确认剧情。

## 3. 执行后必须复验（不能只靠事前预测）

1. 记录改前片段或父版、修改后的差异及受影响的前后文、邻章和账本。逐项检验**预期好处是否实现**，同时主动寻找新增的阅读损害和事实冲突。
2. 按 [统一核心协议](review-core.md) 只复验受影响的七维、37项 AI 味线索、反方证据与时间轴/人物/相关道具连续性；旧 G1—G4 只按疑点取证，不强制逐关重跑。自动机检通过不代表净收益为正；对比要有人工语义判断。
3. 若实际收益不明显、低于损害，**回滚该改动，保留原文或重新提出更小方案**；不能因为改稿已完成就保留低质量变更。
4. 严格尊重既有审批与事实写回顺序。MD→TXT、索引/账本等派生同步虽属技术步骤，仍要核对准确性及无新冲突，不能借同步夹带未经评价的正文改动。

## 4. 审稿报告与执行清单

审稿报告的「问题清单/修改建议」后或「结论」前，固定追加 **《修改收益—损害评估》**，逐项填写：

| 修改 ID | 原文作用与问题证据 | 预期收益 | 潜在损害 | 净收益判断与理由 | 决策 | 改后复验/回滚 |
|---|---|---|---|---|---|---|
| M-001 | {真实章节/行/功能} | {具体改善} | {具体丢失或风险} | {收益>损害 / ≤ / 不确定，理由} | {执行/替代/保留/待决} | {实测改善/新增损害/已回滚/未执行} |

- **只审不改**：列评估与推荐，不虚构已实施或已复验。
- **自动修改**：仅执行已授权且收益明确大于损害的项。P2/P3 不是必改清单；不改的项也要留下判定依据。
- **最终交付**：说明“建议 n 项、实施 n 项、保留 n 项、待裁决 n 项、回滚 n 项”，逐项可追踪；严重问题仍未修复须 BLOCKED。
- **评价原则**：保留与原文有关的审稿证据，不用综合评分升高来掩盖人物、情节或信息边界的局部退步。净收益评估为修改门禁，不新设第八评分维度，不重复扣分。
