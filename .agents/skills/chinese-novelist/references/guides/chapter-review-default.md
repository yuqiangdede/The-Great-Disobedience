# 通用中文小说·单章正文质量审查默认执行提示词

> **通用范围：适用于各种题材、文风、叙事人称与篇幅的中文小说，不绑定任何书名、人物、世界观、时代、势力、专业背景或专用目录。** 本文件是执行模板，不是第二套评分协议；权威裁决、37项定义、权重和优化轮次以 [review-core.md](review-core.md)、[ai-style-37-checks.md](ai-style-37-checks.md) 最新版本为准。按当前项目明确的写作规则、作品定位和作者当次要求执行，不能把示例作品的文风或题材当作通用标准；旧 G1–G4 等历史材料不叠加成独立关卡。

## 0. 自动触发与参数

- 用户要求对**正式正文**进行「审核、审查、质量检测、检查、复审、去 AI 味、优化后复核」等，无论有没有粘贴审稿提示词，**必须自动读取并执行本模板**，不允许只依据名称打分或只跑机械脚本；对「检查第X章」等明确指向正式正文的短指令亦同。
- 目标参数来自本次用户要求和当前项目索引：`【作品（可选）】`、`【卷/篇目（可选）】`、`【章节编号/名称/文件路径】`、`【审稿范围】`。不假定固定卷数、编号规则、章节长度或插章制度；整卷／多章请求逐章执行并总结跨章问题，不以抽样冒充全量审稿。
- 用户只提交卷纲、章纲、章节简写、任务卡而非正文时，**改走 [outline-review.md](outline-review.md) 的剧情模式**，不套用正文37项语言检测，也不强制修改正文。混合任务分流处理。
- 用户本次明确“只审不改／只给意见”时仍走完整阅读与裁决，但禁止写回；其余主动质量审核按已有授权自动实施有正净收益的最小修改。不能自动决定的重大设定、人物命运与情节改动交作者裁决。
- 版本控制与交付方式遵从本次用户授权及当前项目规则（直接写入、提交、PR 或只读等），不得把某一作品的仓库习惯强加给其他项目；没有本地脚本环境不能把远端写文件当成执行了本地校验。

## 1. 审查前：实际核对与登记

1. 确认当前作品、项目根目录、正文路径、版本/工作分支（如有）。读取本 Skill 的 `SKILL.md`、`review-core.md` 和37项原表；按实际存在情况读取项目配置（如 `novel.project.json`）、项目级 Agent 约束（如 `AGENTS.md`）、文风规范和作者明确要求。配置缺失时按现有资料确定规则，不虚构固定文件名或路径。
2. 按当前作品实际目录和已有资料，定位并阅读与本章相关的任务卡、卷/章纲、章节简写、人物档案、世界观、时间线、关系、组织制度或专业知识设定；不存在的资料登记缺失或不适用，不强制生成某种题材才需要的档案。
3. **完整读取**本章正式正文（以当前项目指定的唯一正文源为准，可能是 MD、TXT 或其他格式）；如项目维护阅读副本、分卷合订本或其他导出格式，核对这些文件。按必要性读取相邻章节、人物状态、时间线、关系和伏笔记录，检查连续性；没有对应副本时不凭空声称已同步。
4. 严格区分**已写入正文的已发生事实／确认设定／未经批准的规划／角色或审稿者推测**。发现冲突追溯权威来源和生效时间，不用最近时间戳粗暴覆盖已发生事实。
5. 登记真实读取的文件、分支/版本、读取范围及缺失资料。将缺失分为“阻断性（关键正文/权威事实，暂停相关写入与评分）／局部影响（受影响裁决待核实，其余继续）／非阻断或不适用”三级。没有读到的文件不得声称已核对；无法充分读取时不可给伪精确分或虚报 PASS。
6. 写入前检查当前分支与可见已有差异，保护与本任务无关的改动；无法看到本地工作区时不得声称已核实本地未提交修改。未获明确授权不自动提交、推送或创建 PR。

## 2. 剧情层独立审查（先于语言评判）

对每个主要场景核查：**目标→信息与证据→人物选择→实际行动→真实后果**，不要求机械套模板，但事件因果须成立。

- 人物动机、身份、能力、立场、当时知情边界、群像独立判断及关系发展是否可信；是否为了剧情让对手降智、让人物凭空知道答案。
- 时间、地点、空间、行动条件、身体状态、因果后果和世界规则是否自洽；涉及职业、战斗、侦探、医学、法律、科幻、玄幻等特定题材时，**仅按本章实际内容与已确立的题材设定**追加相应专业合理性检查，不预设所有小说都有战术、武器、编组或特殊能力。
- 场景是否新增事件、风险、关系、情绪质感、代价、情报或伏笔；是否同构重复、巧合解围、无代价选择、机械反转或突然揭示。
- 开篇即时问题、过程阅读动力、场景节奏、信息释放、章尾悬念与追更吸引力是否有效；不能为造钩子强改事实或增加不合理危机。
- 记录剧情问题与最强合理反证；**不调用简写专属七维表为正式正文重复评分**。

## 3. AI 味37项逐项、逐段深审（本次最高优先级）

从 `ai-style-37-checks.md` 读取**完整37条**，每项逐一裁决；重点复核第32—37项：程序化、公文式绕弯；免责腔/冗余否定；多人声口同质化；翻译腔及指代语序；模板句/虚假叙事增量；重复/机械修辞节奏。不得自行增设第38项。

**必须通读每个自然段，结合相邻段落和完整场景做语义检查，禁止仅扫关键词。** 审查前按正文源建立稳定自然段编号及应审段数；长章按连续段落分块，并检查块间连接、相邻对白和重复模式；记录实审段数、遗漏数及覆盖率。未实际达到100%不得宣称全文深审完成。每段逐点核问：

1. 此段新增或延续了什么事件、人物关系、情绪、信息、风险、伏笔、氛围或节奏？删掉某句话是否损失有效文学作用？不能按孤句信息密度定错，应评估相邻段落组合效果。
2. 低头、沉默、移开视线、按纸、停顿等微动作是否符合现场行为目的，还是用微动作伪造叙事意义？
3. “不是……而是……”“没有……只是……”及机械对仗/排比是否推动真实理解，还是制造假深度？
4. 是否用抽象概念代替具体选择、动作和实际后果？是否在段尾不必要地解释心理、主题和象征？
5. 是否连续多个段落重复“动作→解释→结论”、同类句首句尾、同一修辞和停顿节奏？
6. 中文语序、中心词、指代、搭配、动作主体与句间关系是否自然；是否一句能讲清却绕成多句，迫使读者回读？
7. 是否存在不必要的免责声明、公文流程复述、背景复读、修饰副词堆叠或翻译腔？

**人物对白逐句专项**：先确定说话人，再按其身份、性格、文化程度、职业、情绪、权力关系、现场目标和知情边界检查。严查多人共用完整书面逻辑、责任宣言、抽象格言、密集比喻、公文腔和过度工整的台词。连续阅读同场多人的往来，不能摘孤句判错。

**必须同时寻找反证**：符合题材的专业表达、真实手续、人物口头禅、有目的的重复、有效留白、慢场景、必要的不确定性、能体现人物的简洁或特殊句式不得机械删除。不能以通用的“朴素/克制/短句/低修辞”偏好压制已确认的抒情、幽默、热血、诗性、实验性或其他合理文风；不要凭 AI 特征推断作者身份或编造生成概率。

每条规则裁决仅使用：`不明显／待复核／明显／证据不足／不适用`。37项均记录规则编号和最终裁决；**仅真实命中的问题**强制记录段落号、短引文、上下文、阅读损害和最强反证；不适用记录依据，无问题项不虚构命中句。**同一根因可关联多个规则，但只记一个真实问题、只扣一次分。**

## 4. 独立反方审阅与主审复核

有真正可用的独立子智能体时，在主审最终定案前发起**独立阅读**，不预先发送主审评分或修法；要求反方给出有证据的最多3—5处有力质疑、每处最强反证、值得保留的有效原文，且反方不得直接改稿。主审对每项裁决 `成立／部分成立／被推翻／待核实`。

不能真实派生子智能体时，改为**单模型隔离式反证审查**，明确写“非独立子智能体审阅”。没有真正运行的审阅/第三方工具不得标“已完成”。

## 5. 两套验收：正文评分与 AI 味专项分开

**唯一评分口径及专项结论**以 [review-core.md](review-core.md) 第四节为准，不在执行模板重复维护权重或独立发明门禁。记录正文七维各项 0—10 分（语言维度占总分55%，其下五子项单列）、折算总分 /100、实质 P0/P1、AI味37项逐条裁决与专项结论；篇幅、机械脚本和工程交付分别记录。**37项专项不单独打分或再次加权**。改前冻结同章、同量表、同一证据定位与问题台账；改后以原文/改文对照寻找新增损害，任何分数变化必须给出具体原因，未受影响维度原则上不改分，不能为证明有效而抬分。

## 6. AI 味疑点主动核实 + 净收益自动修订

- **明显**：必须主动寻找净收益为正的最小改法，直接修改并复验；无安全有效改法则登记未解决，不可虚报通过。
- **待复核**：必须回到真实原文、上下文、人物声口和任务资料补证；成立/部分成立且净收益为正则修改；被反证推翻则改判“不明显”并保留；仍无法确认则登记阻塞，不可跳过。
- **证据不足**：必须主动查询缺失资料并尝试定案；证据仍不足就说明具体缺什么、为什么无法核实，不凭空改稿。
- **不明显**：保留，不作无意义美化；**不适用**：不修改。

**只有核实过并裁决“不明显”或“不适用”的项能直接跳过修订处理。** 但“必须处理疑点”不等于“强行改写每条嫌疑句”：确证问题没有正收益修法也不得改坏原文，须登记为未解决。

每项方案先比较：**收益**（语言更符合当前作品风格、对白真实、信息清晰、叙事增量、因果准确）与**损害**（人物声口、项目文风、必要留白、情绪积累、伏笔、知情边界、时间/设定）。仅净收益明确大于损害才允许落笔。按**词语→句子→邻句→局部段落→必要场景局部**优先修改；禁止无收益整章重写、制造另一类 AI 模板或补造人物背景、道具、能力及规则。

逐项记录真实的“改前→改后”、位置、理由、收益、风险、验证和回滚。哪怕评分上升，只要人物、情绪、事实或自然表达受损，负收益修改也必须回滚；回滚的实际尝试计入优化轮次；不得为凑次数强改。

## 7. 单章优化闭环

**阈值、边界值、末次补优化及上限只读 [review-core.md](review-core.md) 第五节**，此处不复制另一套判定表。高分章节也允许零修改；低分章节超过75后的补充优化仅在轮次充足且正收益确凿时执行。每轮按章记录原分、确证问题、正净收益修订、复验分数、回滚与剩余轮次；AI味专项独立重判。没有正收益改法、重大事实待裁决或到达上限时如实停止，不得凑轮次或用文学分数替代专项通过。

## 8. 复验、同步与真实执行边界

每轮改后复读修改句段和相邻场景，重新裁决受影响 AI 味规则，核对对白、剧情、人物声口与知情边界、世界观、该题材适用的专业细节、必要邻章和伏笔；发现新问题或净损害则回滚。

根据项目配置确定**唯一正文源**并只修改该版本；如当前项目明确要求 TXT、合订本或其他阅读副本，则执行其现有导出命令并检查标题、顺序、正文内容、段落和格式。比对时按项目正式排版规则规范化标题、段首缩进和场景空行，勿把合法的 MD/TXT 版式差异视为正文不同；不允许把 TXT 反写成第二份可编辑源。导出路径和命令必须从当前项目的配置、脚本说明或实际文件获得，**不固定使用任何作品目录、文件名或工具命令**。

若当前项目使用本 Skill 提供的 `scripts/export_reading_txt.py`，可按其真实参数对实际章节导出并执行可用的 `--check`；其他项目则使用其自己的构建/导出流程。**未运行脚本不得报告同步 PASS**；仅能通过 GitHub API 写文件时须说明缺失的本地导出和核验步骤，不能把预期当成已完成。

## 9. 审稿记录与最终回复

若项目已有审查报告归档路径，沿用其规范；不要制造第二套重复报告。完整报告保留：

1. 实读文件/版本/范围、缺失资料及等级、自然段应审/实审/遗漏/覆盖率、工具执行状态与反方方式。
2. 剧情问题与证据/反证/裁决。
3. 改前改后七维分项、语言55%下的五子项、总分及每一处评分变化的证据。
4. 37项规则**逐项裁决**（包括“不明显/不适用”）、重点段落证据。
5. 反方攻击、最强反证与主审采纳/推翻情况。
6. 最小修改的收益/损害、改前改后、实改/保留/回滚和轮次。
7. 正文唯一源与当前项目要求的各类导出副本实际同步情况、执行命令和检查结果（不存在的交付物标不适用）。
8. 作者待决及未解决问题。

AI 味统计必须区分“规则项数”和“问题落点数”，记录初审明显/待复核/证据不足、实际修改数、复验解决数、反证推翻数、最终剩余数；不得拿37项检查结果冒充37处问题。最终明确列出文学质量、AI味专项、工程交付、MD与各派生阅读版同步、独立反方的真实状态。

**对话最终回答**按顺序给出：①实际执行范围与反方方式；②剧情裁决；③完整七维改前/改后评分表；④AI味专项（逐项展示所有仍为或曾为“明显/待复核/证据不足”的项，附原文短引、影响、反证和结果；其他项留完整报告）；⑤反方裁决；⑥收益—损害评估；⑦真实改动及回滚；⑧文学质量、AI味专项、工程交付、正文与适用导出副本的同步状态及待作者裁决事项。

**不得虚报已读、已改、已提交、已运行脚本、独立子智能体完成或文学/工程 PASS。发现无问题要明确保留，不制造问题。**
