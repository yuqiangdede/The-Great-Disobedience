# 历史四关操作卡（参考案例，不是执行入口）

> 旧 G1—G4 曾用于逐章顺序校验，现已归并入 [唯一审稿核心](../guides/review-core.md) 的五类问题与 [37项](../guides/ai-style-37-checks.md)。下列内容保留实践经验，**不要再执行四轮强制流程、不创建第二份强制四关报告、不凭脚本 BLOCKED 推定文学质量失败**。

## 四关可借鉴的局部改写

| 历史来源 | 实际可用的检查思路 | 必须保留的反证 |
|---|---|---|
| [G1 Humanizer-zh](gate-1-humanizer-zh.md) | 检查假对比、句尾无效升华和空泛强调 | 有功能的事实辨识、主题回响、文学修辞 |

## 选用辅助工具时的真实记录

```bash
python {skillBaseDir}/scripts/scan_ai_tone.py <章节文件路径> --project-dir <项目根目录> --auto-report --json
```

脚本输出是候选与工程信息，需记录是否真的运行、实际参数、结果、候选对应的原文位置、合理反证。脚本中的历史 G1—G4 或 WARN/BLOCK 标志**不是**37项独立语义审查的判决，不要求为了清零候选而改坏叙事。实质问题只归入一个主问题并检查收益/损害；详细规则参考 [净收益门禁](../guides/change-benefit-gate.md)。

## 旧经验的三条硬边界

1. 不为消除 AI 味删掉伤病、数量、时间、装备信息、人物目的、条件/否定、伏笔和真实不确定性。
2. 不为了制造不同句长、词频或“人工感”硬拆句、加口语口头禅、删除有用慢场景。
3. 如需反方，遵循 [反方证据方法](adversarial-ai-review.md)：真实可委派才称独立；否则明确单模型反证，改后复核受影响范围。

只需在**正式审稿报告中**登记主问题、证据、反证、改动与复验。完整历史实例与研究继续保存在本目录的其他参考文档中。
