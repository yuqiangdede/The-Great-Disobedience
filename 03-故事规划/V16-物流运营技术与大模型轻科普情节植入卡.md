## 一、嵌入的基本方法

1. **先情节后术语**：人物遇到一个生活问题→做一个看得见的动作→赢/输一笔具体生意→顺手用一两句话说透原理。术语可不出现，懂行者能认出原理即可。
2. **篇幅限额**：每章至多一个主知识点；需要时再加一个不解释的配角细节。每处常规解释约30—90汉字，极特殊单场景最多150字；前五章更短。纯知识说明不单独成段，不允许专门出现“科普时间”“你知道吗”。
3. **真实行业差异**：外卖即时配送≠寄递快递；普通仓配≠特种物流；订单服务商≠有资质快递经营主体；智能快件箱显示投递≠用户确认领取。涉及法定收寄、验视、实名及合同责任由有资格主体处理。
4. **技术不降智**：导航、分拣、柜机、识别、报价和普通算法多数时候正常有效；反派的设备和补贴可真赢。许砚卖的是异常交接、现场判断、到岗和赔付保障，不能凭一眼“看穿AI全部错误”取胜。
5. **技术不越权**：模型生成建议不等于授权，自动日志不等于人亲自到岗；AI不能签免责书、自动扣掉他人责任或遥控专业设备。2049只是跨机构高影响授权断续，不是全球芯片和低风险工具全部报废。
6. **以收益落地**：采用某技术细节，只能让已有V16赢法更容易理解，不得替代原有具体人、买方、合同、实收、工资和代价。V16财务账本金额、资质与赔偿不被新细节暗改。
7. **2061设定与2026资料分离**：下文引用的是截至2026年可核的技术原理、行业做法及中国法规参考；2061虚构平台名称、系统功能、费率、时效、法律状态要在剧情世界内部自洽，不能把现行法规宣称为2061必然原样有效。

## 三、允许自然露出的物流运营常识（不是正文讲义）

| 概念 | 面向普通读者的讲法 | 可写/不可写边界 |
|---|---|---|
| 动态派单 | 单子不只是看谁离得近，还要算骑手正在送什么、商家几时出餐、能否按时合法交付 | 平台推荐不是不可改变的神谕；司机仍受路权/交通规则约束 |
| VRP车辆路径规划 | 多车多单安排路线；要同时考虑运力、时间窗、先取后送、合法道路 | “最短地图路线”不能无视卸货口与门禁；求解器也不保证复杂大实例总是全局最优 |
| ETA预计到达 | 结合路线、路况和作业耗时估计的时间，不是承诺事实 | 估计会变化，可用实际到岗记录复核 |
| OMS/WMS/TMS | OMS管订单，WMS管库内实物和拣货，TMS管运输；同一退货在三个系统的状态不一定同时更新 | 这些是常见功能分工，并非每家站必有三套独立系统 |
| 扫描事件链 | 生成/入库/分拣/出库/到站/派件/领取等事件各自留下记录 | “扫码成功”不能直接推出“真人收到了”；不得伪造物流轨迹 |
| 逆向物流 | 买家退货往回走，还涉及验货、退款、重新入库或报损 | 不把任何退货默认等同原件完好 |
| SLA | 买方购买有边界的时效、到岗、赔付与售后承诺 | 服务时间、岗位人数、赔付范围要实说，不承诺无限责任 |
| 单位经济/贡献毛利 | 收入减掉这一单可归属司机工资、空跑、耗材、预期赔损后，才知道是不是值得接 | 毛利不等于公司净利润，更不等于老板个人存款 |
| 备班与容量管理 | 看起来“闲着”的人也可能需要付待命费；备用不代表免费 | 多城同一时窗不能一人多用 |
| 需求预测 | 根据历史活动估计忙闲，再备车和人 | 直播促销、突发停电等会令历史预测失效，不能准确预言所有订单 |

| 故障降级 | 智能柜坏了，经过授权转人工预约、退款或延期 | 不代表骑手有权打开柜锁或代客户签收 |

## 四、允许自然露出的大模型基础知识（贴合2049—2063世界观）

| 知识点 | 正确浅白理解 | 适合表现的章节 |
|---|---|---|
| 训练 vs 推理 | 训练是在大量样本上学规律，推理是拿现有模型处理当前订单/问题；不是每接一单就自动重训练一次 | 042、057、102 |
| Token | 大模型读写文本会切成文字片段（token）；它处理语言概率，不等于知道某个骑手有没有上门 | 012、048 |
| 生成式AI vs 优化算法 | 客服回复可由语言模型起草；多车路径还需要规则、约束与优化求解器；二者常协同，不是一种“万能神经网络” | 004、048、061 |
| 幻觉/编造 | 模型可能生成听着合理却没有事实依据的答复，必须查原始订单、扫码和人证 | 001、045、048 |
| RAG检索增强 | 先查有权限的工单、商户约定和已确认知识，再让大模型整理回答；**检索本身也可能漏资料，引用也可能错** | 039、048、111 |
| 向量/语义检索 | 可以按意思找相近客诉，比如“柜门开过没取到”和“扫码后没见到货”，但相似不是同一包裹证据 | 039、045 |
| 模型置信度/校准 | 系统给高分只能表示按某种算法很有把握，不保证地上真有人或事实成立 | 012、015、120 |
| 数据分布变化 | 白天高频出餐学出的经验，到了午夜、洪灾、断电可能不准；需要真实复测 | 057、088、122 |
| 人在回路 | 关键交接、授权和高风险动作须由有权限的人确认；不是叫“真人核实”就自动算完成 | 014—018、120、126 |
| AI系统不等于LLM | 智能柜传感器、规则引擎、定位、优化求解器、语音模型、大语言模型各司其职；某类跨机构授权断续不意味其他都失灵 | 全书设定 |
| 自动化偏差 | 人容易因屏幕显示绿色就不再核现实，这是一种人的管理失误；技术不是所有责任的替罪羊 | 014—015、105、120 |
| 数据主权/接口权限 | 能查记录、能生成建议、能修改工单、能签署授权是不同权限；读到数据不等于可执行跨机构高风险动作 | 007、058、120 |
| 评测指标与反馈 | 报告中“标准件准点”若不含午夜异常件，不能证明异常售后也同样好；比较前要对齐服务范围 | 038、045、102 |

## 五、场景写法样例（仅演示表达方法，不构成新增剧情）

**001｜时间戳不是收餐签字**  
崔明盯着他：“系统上不就写着你超时？”  
许砚把原单和改址消息并排放大：“你改的地址是八点十七，系统还拿八点零五的旧门口算时间。你说我偷懒，让店员看看我八点十二到的哪扇门。”  
店员一看屏幕，抬头认了人。许砚没说平台已经撤评，只把申诉单提交上去。  
*作用：把证据与AI/算法边界写成当场反击，不讲技术课。具体时刻为示范台词，正式正文不得与原卡或核验后的时间冲突。*

**022｜高价夜班靠算账，不靠突然暴富**  
阿灿盯着报价：“两千六，听着真多。”  
许砚在纸上划掉工钱一千六百五、准备三百五，又点了点自己那份两百：“你以为全进我兜？这是两家老板合起来买的，空车不再跑两遍。”  
*作用：把边际成本讲成骑手熟悉的赚钱逻辑；履约企业保留400元、付款主体及到账时点仍依原V16账本，不能把上述报价直接说成“全已到账”。*

**048｜大模型能回复，不代表能替人接电话**  
柜机客服三秒回了三段解释，商户看完更火：“它让我耐心等，凌晨谁来取走这箱东西？”  
许砚没有骂系统没用，只把有薪夜班的真人值守时间和补送价摆出来：“你买的不是一句道歉，是两点有人接电话。”  
*作用：AI能力是真实存在的，主角只补其商业末端责任缺口。*

## 六、禁区与验收

- 禁止新增“主角掌握私有超级大模型/系统后台管理员权限/人形机器人军团/黑进平台改分/无资质跨城揽收”作为捷径。
- 禁止泛化“AI都会幻觉”“人工永远更准”：AI正常件仍高效且可带来真实竞争压力；真人一样会犯015/120这类严重错误。
- 禁止解释成“2049年因为模型训练坏了所以所有物流失灵”；既定原因是**跨机构高影响授权部分断续**，低风险系统仍能运行。其深层因果若V16未确认，不做新的世界观解释。
- 禁止拿AI建议当法律许可、客户同意、专业岗位资格或物理设备操作依据；尤其不可新编120水务安全备份失效、122—127水文数字。
- 禁止引用真实2026企业的商业机密、平台特定派单惩罚细节、算法参数、未经核实的罚款金额；虚构2061企业须自洽。
